Rules

Fault rules, in order: the first enabled rule that matches a request applies, and new rules go on top. A rule in a set goes away with the set (State page).

How rules are evaluated
  1. Classify: the path gives the request kind; an unknown endpoint answers 404.
  2. Identify the caller: invalid credentials answer 401 before any rule.
  3. Rules: the first enabled matching rule applies its effects in this order: headers (kept on whatever answer follows), latency, reset, status; a rule with only headers, latency, a quota or pass lets the request go on.
  4. Authorization: grants and the host's auth scheme; 401 without credentials, 403 without the right.
  5. Quota: the rule's quota counts the request, 429 when exhausted; a request refused at step 4 counts nothing.
  6. Serve the synthetic image, or forward to the proxy backend.

Pass matches and stops the evaluation without a fault: put it above a broader rule to exempt a narrower target. Repo globs: * is one path segment, ** any number; a pull by digest has no tag and matches a tag pattern only when the kinds name manifest-by-digest.
